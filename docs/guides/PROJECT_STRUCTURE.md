# Project Directory Structure

## Documentation and Planning Files Location

This document specifies where all planning and progress tracking files should be stored in your project.

---

## 📁 Recommended Directory Structure

```
/home/username/projects/itervel-platform/
│
├── docs/                              # All documentation here
│   ├── planning/                      # Planning documents (one-time creation)
│   │   ├── prd-brief-for-opus.md     # Brief you give to Opus
│   │   ├── PRD.md                     # Full PRD generated by Opus
│   │   └── development-plan.md        # Development plan from Opus
│   │
│   ├── progress/                      # Progress tracking (auto-updated)
│   │   ├── DEVELOPMENT_PROGRESS.md   # Main progress tracker (Claude updates)
│   │   └── progress-dashboard.html   # Optional visual dashboard
│   │
│   └── guides/                        # Reference guides (from this session)
│       ├── QUICK_START_GUIDE.md
│       ├── DOCKER_USAGE_GUIDE.md
│       ├── DEPLOYMENT_GUIDE.md
│       └── PARALLEL_DEVELOPMENT_GUIDE.md
│
├── app/                               # Laravel application code
├── database/                          # Migrations, seeders
├── resources/                         # Frontend code (React)
├── tests/                             # Test files
├── public/                            # Public assets
├── storage/                           # Logs, cache, uploads
├── .env                               # Environment configuration
├── docker-compose.yml                 # Docker configuration
├── Dockerfile                         # Docker build instructions
└── README.md                          # Project readme

```

## 📝 File Descriptions

### **Planning Documents (docs/planning/)**

**Created once, referenced throughout development:**

1. **prd-brief-for-opus.md**
    - The brief you created (from our session)
    - Used to generate full PRD
    - Keep for reference

2. **PRD.md**
    - Full Product Requirements Document from Opus
    - Comprehensive specs for entire project
    - Claude references this when building features

3. **development-plan.md**
    - Detailed build plan from Opus
    - Features broken down by phase
    - Dependencies and build order
    - Claude follows this plan

### **Progress Tracking (docs/progress/)**

**Auto-updated by Claude during development:**

1. **DEVELOPMENT_PROGRESS.md**
    - PRIMARY SOURCE OF TRUTH
    - Updated after every feature/checkpoint
    - Shows what's done, what's next
    - Resume instructions
    - Session history

2. **progress-dashboard.html** (optional)
    - Visual HTML dashboard
    - Generated from DEVELOPMENT_PROGRESS.md
    - Open in browser for pretty view

### **Reference Guides (docs/guides/)**

**One-time reference documents (from our session):**

1. **QUICK_START_GUIDE.md**
    - How to use autonomous development system
    - Workflow overview
    - First session instructions

2. **DOCKER_USAGE_GUIDE.md**
    - Complete Docker setup
    - Daily workflow commands
    - Multiple agents setup
    - Troubleshooting

3. **DEPLOYMENT_GUIDE.md**
    - A2 hosting setup
    - GitHub Actions CI/CD
    - Deployment workflow

4. **PARALLEL_DEVELOPMENT_GUIDE.md**
    - How to run multiple agents
    - Git worktrees setup
    - Parallel development strategies

## 🎯 Why This Structure?

### **Benefits:**

✅ **Clear separation** - Planning vs Progress vs Guides
✅ **Easy to find** - All docs in one place
✅ **Git-friendly** - Can commit docs/ folder
✅ **Clean root** - Keeps project root uncluttered
✅ **Standard practice** - Industry convention

### **Claude Code Behavior:**

When Claude Code runs in `/home/claude/projects/itervel-platform/`:

1. **Looks for planning docs in:** `docs/planning/`
2. **Updates progress in:** `docs/progress/`
3. **References guides from:** `docs/guides/`
4. **Creates code in:** `app/`, `resources/`, etc.

## 🚀 Initial Setup

**Before starting development, create the structure:**

```bash
cd ~/projects/itervel-platform

# Create documentation directories
mkdir -p docs/planning
mkdir -p docs/progress
mkdir -p docs/guides

# Copy your planning documents
cp /path/to/prd-brief-for-opus.md docs/planning/
# (PRD.md and development-plan.md will be added after Opus generates them)

# Copy reference guides (from our session)
cp QUICK_START_GUIDE.md docs/guides/
cp DOCKER_USAGE_GUIDE.md docs/guides/
cp DEPLOYMENT_GUIDE.md docs/guides/
cp PARALLEL_DEVELOPMENT_GUIDE.md docs/guides/

# DEVELOPMENT_PROGRESS.md will be created by Claude in docs/progress/
```

## 📖 How Claude Code Uses These Files

### **Session 1 (Initial Prompt):**

```bash
# You run:
docker compose exec app bash
claude-code

# You paste initial prompt (updated version)
# Claude automatically:
1. Reads docs/planning/PRD.md
2. Reads docs/planning/development-plan.md
3. Builds features
4. Creates docs/progress/DEVELOPMENT_PROGRESS.md
5. Updates it after each checkpoint
```

### **Session 2+ (Continuation Prompt):**

```bash
# You run:
docker compose exec app bash
claude-code

# You paste continuation prompt (updated version)
# Claude automatically:
1. Reads docs/progress/DEVELOPMENT_PROGRESS.md (to know where to resume)
2. Reads docs/planning/development-plan.md (for feature specs)
3. Continues building
4. Updates docs/progress/DEVELOPMENT_PROGRESS.md
```
